# 研究路线图（RESEARCH ROADMAP）

> 本文件记录**尚未实施、需要实验验证**的研究方向。
> 每项研究需说明：研究目的、预期收益、技术风险、所依赖的已有模块、
> 需要的对照实验、以及「什么情况下值得正式实施」。
> 在满足实施条件前，**不要直接全面实施**。

## 研究 A：AlphaZero 式 MCTS 自我对弈

- **研究目的**：用 Policy Network 提供动作先验、Value Network 评估叶节点、MCTS 产生访问次数分布、自对弈生成训练数据。
- **预期收益**：摆脱手工评估函数，获得真正"学会"的棋力，且天然支持课程学习。
- **技术风险**：
  - MCTS 单机串行慢，家用机算力受限。
  - 批量 GPU 推理与树搜索的调度复杂，处理不好反而更慢。
- **依赖模块**：`environment`（State、Board、编码）、`engine/alphabeta`（可作教师）、`network`（待建）。
- **对照实验**：
  - 纯 MCTS（无网络先验） vs 带 Policy/Value 先验的 MCTS。
  - 批量评估 vs 延迟评估的效率差异（见下）。
- **实施条件**：完成轻量网络原型、跑通单机 GPU 批量推理、明确延迟评估策略后。

### 特别关注：GPU 批量推理

- 不要每生成一个子节点就调用一次 PyTorch。
- 考虑将多个对局产生的待评估状态收集到同一 Batch，统一送入 GPU。
- 但不能仅为了凑 Batch 就提前计算所有子节点；需研究「批量评估 vs 延迟评估」的效率差异。

## 研究 B：知识蒸馏

- **研究目的**：用更强的教师 Agent 生成棋谱，训练轻量学生网络。
- **预期收益**：学生网络继承教师棋力，推理快、体积小，适合本地部署。
- **技术风险**：
  - 教师棋谱可能存在规则不兼容（如连珠禁手棋谱不能直接用于自由规则）。
  - 蒸馏会丢失搜索带来的战术精度。
- **数据形式**：Board State、Policy Target、Value Target、合法动作掩码、棋局阶段与战术类型。
- **教师来源**：现有战术搜索引擎、后续优化的搜索 Agent、外部成熟五子棋引擎（需核查规则兼容性）。
- **对照实验**：蒸馏学生 vs 直接自对弈训练；不同教师强度下的蒸馏效果。
- **实施条件**：有可用的强教师 + 统一训练数据格式（见 Task 7）后。

> ⚠️ 知识蒸馏是**训练方式**，不是独立的部署架构，不要混淆。

## 研究 C：课程学习

- **研究目的**：研究不同棋盘规模（7×7 / 9×9 / 15×15）的渐进训练与权重/策略迁移。
- **预期收益**：小棋盘快速收敛，再迁移到大棋盘，可能显著降低训练成本。
- **技术风险**：
  - 改变棋盘规模若同时改变胜利连子数，会改变游戏规则和策略结构，不可直接迁移。
  - 小棋盘训练效果好 ≠ 具备 15×15 棋力。
- **依赖模块**：`environment`（已参数化 size 与 win_length）。
- **对照实验**：固定 15×15 直接训练 vs 7→9→15 渐进训练；固定「连五」规则下的迁移效果。
- **实施条件**：确认小棋盘能带来正向迁移后，再纳入正式训练流程。

> ⚠️ 不要照搬「3×3 连三、5×5 连五」的做法——改变连子数会改变游戏规则。

## 研究 D：神经网络结构消融实验

- **研究目的**：确定最优轻量网络结构。
- **预期收益**：在棋力与推理速度之间找到最优平衡。
- **对比维度**：
  - 2 通道 vs 3 通道输入
  - 是否加入最后一次落子信息
  - 是否加入人工棋形特征平面
  - 不同 ResNet 深度
  - 不同隐藏通道数
  - Value Head 不同结构
  - 全局平均池化的效果
- **风险**：盲目堆输入通道不一定更好，需实测。
- **实施条件**：有可复用的网络训练脚手架与统一评估标准后。

## 研究 E：经验回放与训练策略

- **研究目的**：确定训练策略超参数。
- **对比维度**：滑动 Replay Buffer、历史数据保留比例、难例过采样、八种棋盘对称数据增强、Policy/Value Loss 权重、根节点探索噪声、自对弈温度参数。
- **预期收益**：提升训练稳定性和数据利用率。
- **风险**：
  - 视频中的 50,000 经验池、0.4 价值损失权重、0.6 回传衰减是**博主经验值**，不是标准参数。
  - 第一版应优先采用标准 Policy-Value 训练目标，再通过消融确定参数。
- **实施条件**：跑通第一版训练后，用消融实验逐项确定。

## 研究 F：NNUE / MixNet + C++ 搜索（备选）

- **研究目的**：若 Python + PyTorch 混合推理无法达到目标棋力，研究 C++ 搜索引擎、NNUE 增量更新、棋形查表、MixNet、Cython/原生扩展。
- **预期收益**：大幅降低延迟、提升搜索深度。
- **技术风险**：工程量大，跨语言维护成本高。
- **实施条件**：仅当 Python/PyTorch 路线被证明无法达标时启动。**当前不进行大规模 C++ 重写。**

## 研究 G：不确定度触发的混合推理

- **研究目的**：普通局面用网络直接决策，复杂局面根据不确定度触发有限搜索。
- **预期收益**：在保持低延迟的同时，用搜索兜底复杂局面。
- **触发信号（需验证）**：Policy Top-1 与 Top-2 概率差、战术风险、Value 变化、威胁数量。
- **风险**：
  - 策略概率接近 ≠ 局面危险；策略概率集中 ≠ 动作一定安全。
  - 必须用实际数据验证触发机制，不能凭直觉。
- **实施条件**：有可用的 Policy/Value 网络 + 真实对局数据后。
