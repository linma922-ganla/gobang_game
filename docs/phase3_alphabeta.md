# Phase 3：Alpha-Beta 搜索引擎算法说明

本文档解释 Phase 3 实现的搜索算法工作原理。

## 1. Negamax

Negamax 是 Minimax 的简化形式，核心思想是**统一视角**：

```
score = -negamax(下一层状态)
```

即：轮到对方时，对方会从**对方自己的视角**选择最优，而我们站在自己视角
看这个结果，需要取负号。因此整个搜索只需写一个函数，只需处理
「当前行动方」的视角，无需在 Max/Min 之间切换。

价值函数统一以**当前行动方视角**计算（`evaluate_board(board, player)`
返回 `player` 视角的评分，正值表示 player 占优）。

## 2. Alpha-Beta 剪枝

Alpha-Beta 在 Negamax 基础上维护两个界：

- **alpha**：当前行动方已经能保证得到的最低下界。
- **beta**：对手已经能限制当前行动方的上界。

当搜索某个分支时发现 `alpha >= beta`（该分支不可能比已知更好），
立即剪枝，跳过剩余分支。正确实现时，Alpha-Beta 与不剪枝 Minimax
在同样深度返回**完全相同**的最优分数，只是搜索节点更少。

## 3. 迭代加深（Iterative Deepening）

从 depth=1 开始，逐层加深到 depth=2、3、4……每完成一层就保存
当前最优着法。

好处：
- 配合时间限制，任何时候中断都能返回「最后一个完整完成深度」的结果。
- 浅层结果可用于深层搜索的 Move Ordering（虽然本实现未做跨层传递）。

## 4. Zobrist Hash

对每个 (位置, 棋子颜色) 预生成一个随机整数，棋盘哈希 = 所有已落子
位置对应随机数的异或（XOR）。再额外异或「当前行动方」的随机数，
使「同一棋盘但轮到不同方」哈希不同。

- 落子：`h ^= table[(r, c, player)]`（O(1)）。
- 撤销：再次异或同一值即可恢复（异或自反）。
- 增量更新与全量重算结果一致（已由测试证明）。

## 5. 置换表（Transposition Table）

用 Zobrist 哈希作为键缓存搜索过的局面，避免重复搜索（同一局面可能
由不同走子顺序到达）。每条目记录：哈希、深度、分数、最优着法、
节点类型。

节点类型三种：
- **EXACT**：该深度下分数精确确定。
- **LOWER_BOUND**：分数是下界（发生 beta 剪枝，真实分数 ≥ 此值）。
- **UPPER_BOUND**：分数是上界（发生 alpha 剪枝，真实分数 ≤ 此值）。

读取缓存时必须按类型判断，不能把界错当成精确值（例如 LOWER_BOUND
的分数只有在 `score >= beta` 时才能直接用作剪枝依据）。

## 6. Move Ordering

对候选着法排序，让「更可能好的着法」先被搜索，使剪枝更早发生，
大幅减少节点数。本实现的排序优先级：

1. 己方直接获胜点（增量 `check_win_at` 判断）。
2. 防守对手直接获胜点。
3. 其余用轻量启发式（邻近同色/异色棋子密集度）。

## 7. 时间控制

使用 `time.monotonic()`（单调时钟，不受系统时间调整影响）计算
剩余时间。搜索在关键点检查是否超时，超时则安全退出，返回上一轮
完整完成的迭代结果；若连第一轮都未完成，回退到战术引擎提供的
合法动作。

超时退出时保证棋盘状态完整恢复（每个 `make_move` 都配对 `undo_move`）。

## 8. VCF（Victory by Continuous Fours）

连续冲四必胜搜索：我方不断形成「冲四」迫使对手必须防守，连续逼迫，
最终形成活四或双冲四而必胜。

与普通 Alpha-Beta 不同，VCF 只探索「强制进攻」的着法序列，因此可以
在很深层数上快速搜索。

严格区分三种结果：
- **PROVEN_WIN**：已证明存在强制获胜路线。
- **PROVEN_NO_WIN**：在搜索范围内排除了必胜。
- **UNKNOWN**：搜索预算（深度/时间）不足。

关键原则：**不能因为「没找到必胜」就判定必败；也不能用不完整的
防守枚举错误宣布必胜**。VCF 作为独立模块，在 Alpha-Beta 根节点和
关键战术节点调用，且必须有独立预算，不在每个节点无限运行。

## 9. 候选动作（轻量）

搜索内部节点不使用昂贵的全盘战术扫描（`find_winning_moves` 等），
而是用轻量候选生成：已有棋子周围的空位 + 直接获胜/防守点（增量判断）。
根节点同样使用轻量候选，因为活四/双冲四等必胜点由 Alpha-Beta 搜索
本身覆盖，无需额外的昂贵预处理。

## 10. 终局分数（MATE_SCORE）

终局使用足够大的 `MATE_SCORE = 10_000_000`，并随搜索 ply 调整：

- 己方获胜：`MATE_SCORE - 已搜索节点数`，节点越少（越快获胜）分数越高。
- 己方失败：`-MATE_SCORE + 已搜索节点数`，节点越多（越慢失败）分数越高。

这使 AI 倾向于更快获胜、在必败时尽可能拖延。
